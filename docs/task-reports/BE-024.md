# Task BE-024 — Implement POST /auth/refresh with rotation

## Summary
Implemented `POST /api/v1/auth/refresh` to issue a new access JWT, rotate the opaque refresh token within the same family (`usedAt` / `replacedBy`), detect reuse by revoking the family (`reuse_detected`), and reject revoked/invalid/expired refresh tokens.

## Changes
- Hash presented refresh; reject missing / revoked / expired tokens
- On first use: mark rotated, insert new family member, return new access + refresh
- On reuse of a spent token: revoke entire family and return `AUTH_REFRESH_REUSE`
- Concurrent rotate race treated as reuse
- Response includes rotated `refreshToken` (required for rotation; Backend §2.1 sample omitted it)
